# vLLM 与 SGLang：PR 合并耗时与未回复积压

统计日期：2026-10-31。统计基准时刻：北京时间 10:48:09。
数据源：GitHub GraphQL API，公开仓库的 PR 元数据、会话评论及 reviews。

## 结论

- 整体已合并 PR 中，SGLang 合并更快。
- 排除作者被 GitHub 标记为 OWNER、MEMBER、COLLABORATOR 的 PR 后，两者耗时很接近，vLLM 略快；不能据此断言首次贡献者更容易合入。
- vLLM 开放 PR 总量和超过 90 天的无人回复积压更大。
- SGLang 超过 7 天仍无人回复的数量和比例更高；超过 30 天的无人回复数量略少于 vLLM，但比例更高。
- 不建议仅根据全仓库平均体验选择项目；具体模块的审查人、需求认可和验证条件更重要。

## 统计方法

1. 已合并窗口：2026-08-01 至基准时刻。按不重叠的七天区间检索全部 merged PR，避免 GitHub 搜索的 1,000 条上限，按 PR 编号去重。
2. 合并耗时：mergedAt - createdAt，包含 Draft、等待作者修改、CI 等时间，不能等同于维护者排队时间。
3. 开放 PR：分页遍历两个仓库的全部 OPEN PR。排除 Draft 后比较不同年龄段。
4. “无人回复”：没有作者以外的、可识别的人类账户留下会话评论或 review；作者自己的补充和机器人活动不算回复。它不代表从未在 Slack 等渠道沟通。
5. “非成员/协作者”：作者 authorAssociation 不属于 OWNER、MEMBER、COLLABORATOR。这是仓库身份代理指标，不等于公司外部、新手或首次贡献者。
6. 评论、review 首次各读取 50 条；对尚不能确定是否存在回应的超长历史补充分页。剩余截断记录已经观察到回应，不影响“零回应”计数。
7. 采集期间 PR 状态会变化。开放 PR 数是本次遍历得到的去重数，不是原子快照。

## 三、局限

- 已合并组存在幸存者偏差：没有合并、被拒绝、长期等待的 PR 不进入合并耗时分布。不能解释为“提交后通常五天保证合入”。
- 没有按首次贡献者、模块、改动规模、文档/代码、CI 状态、需求是否被认可分层。
- 非 Draft 不等于已准备好审查；标题可能写 WIP 或 DO NOT MERGE。本次复核发现 SGLang #33638 就属于非 Draft 但标题明确 DO NOT MERGE 的记录。
- 人类回复不等于维护者回复；只使用 GitHub authorAssociation 判断维护者也会漏掉部分社区 reviewer，所以主表使用更可核验的“其他人类回应”指标。
- 未衡量最后一次互动后被搁置多久，也未统计完整的首次人工回复时间分布。
- 开放 PR 的无人回复比例描述积压结构，不是新提交 PR 被忽略的概率，也不是项目合入率。

## 四、对贡献者的建议

在这份数据下，没有证据支持“SGLang 对普通外部贡献者明显更快”。
两者非成员/协作者的成功合并组，中位数约五天，P75 约两周，P90 超过一个月。

优先寻找：

1. 维护者已经明确认可的 Issue。
2. 有具体模块 reviewer/codeowner 愿意接手的任务。
3. 能提供复现、回归测试及相关性能/精度证据的改动。
4. 与当前路线图一致、范围清晰的工作。

未得到任何回应时，应先确认审查人和任务优先级，而不是不断追加代码。
PR 数量和回复速度均不能直接推导 committer 晋升机会。
